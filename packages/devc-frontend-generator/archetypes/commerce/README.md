## 쇼핑몰(커머스)

커머스 Archetype으로 만들었습니다. 상품 목록·상세, 로그인 없이 쓰는 장바구니, 다단계 주문서, PG(결제대행사) 연동 없는 가짜 결제 단계, 주문 완료 화면이 `/shop` 아래에 있습니다. `optimistic-update`(낙관적 업데이트와 되돌리기)와 `multi-step-form`(단계별 검증과 상태 유지) Recipe의 패턴을 씁니다. 머리글의 "쇼핑" 링크로 들어갑니다.

| 화면                             | 하는 일                                                                                                                      | 렌더링                                         |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| `/shop`                          | 상품 목록. 상품마다 이름(상세 링크), 소개, 가격, 재고 안내(품절, 얼마 남지 않은 수량)                                        | ISR(`revalidate = 300`)                        |
| `/shop/products/[productId]`     | 상품 상세와 장바구니에 담는 폼. 없는 상품이면 "찾는 화면이 없습니다"(404)                                                    | ISR(`revalidate = 60`, 빌드할 때 모든 상품)    |
| `/shop/cart`                     | 장바구니. 수량을 줄이고 늘리고 빼며, 합계와 주문하기 링크가 있습니다                                                         | 페이지 뼈대만 미리 렌더링, 장바구니는 브라우저 |
| `/shop/checkout`                 | 주문서. 배송 정보 → 결제 수단 → 주문 확인을 단계마다 검증하고, "결제하기"로 결제 대기 주문을 만듭니다                        | 페이지 뼈대만 미리 렌더링, 입력은 브라우저     |
| `/shop/orders/[orderId]/payment` | 가짜 결제 단계(테스트 결제창). "결제 승인"으로 결제를 확인하고 주문 완료로 갑니다. "결제 취소"는 입력이 남은 주문서로 갑니다 | SSR(주문을 서버가 prefetch)                    |
| `/shop/orders/[orderId]`         | 주문 완료. 주문 번호, 주문한 상품, 배송 정보, 결제 수단                                                                      | SSR(주문을 서버가 prefetch)                    |

- 장바구니는 로그인 없이 쓰는 손님 장바구니입니다. 처음 담을 때 백엔드가 장바구니를 만들어(`createCart`) id를 주고, 앱은 그 id만 브라우저의 localStorage에 둡니다(`src/shared/shop/cart-id.ts`). 담긴 상품과 가격은 백엔드가 들고 있으므로 프론트엔드에는 DB도 세션도 없습니다. 백엔드에 없는 장바구니(404. 오래되어 지웠거나 주문을 마침)는 id를 지우고 새로 시작합니다. 로그인한 사용자의 장바구니를 계정에 묶으려면 백엔드가 accessToken으로 장바구니를 찾게 하면 됩니다(auth Recipe를 쓰면 BFF 프록시가 토큰을 붙입니다).
- 상품 목록과 상세는 ISR이라 빌드할 때 백엔드를 부릅니다. 배포용 빌드에는 `API_BASE_URL`을 넣고, `API_MOCKING=enabled`로 만든 목 빌드(GitLab CI의 `build` 잡, E2E)는 배포하지 않습니다("배포용 빌드와 목 빌드"). 미리 렌더링한 가격과 재고는 늦을 수 있으므로, 장바구니에 담을 때와 주문할 때 백엔드가 다시 확인해 재고보다 많으면 409로 거절합니다.
- 낙관적 업데이트: 장바구니에 담거나 수량을 바꾸거나 빼면 응답을 기다리지 않고 장바구니(쇼핑몰 안 이동의 수량, 줄의 수량·금액, 합계)를 바꾸고, 백엔드가 거절하면 되돌린 뒤 알림으로 무엇을 왜 되돌렸는지 알립니다. 처음 담는 상품은 장바구니의 id를 백엔드가 정해야 하므로 응답을 기다립니다. 상품 상세는 미리 렌더링한 HTML이라 JavaScript가 hydration을 마치기 전에도 담는 폼이 보이는데, 그동안 입력한 수량은 hydration 때 처음 값(1)과 섞이므로 수량 입력과 담기 버튼은 hydration 뒤에 켜집니다.
- 가짜 결제: 주문서를 내면 결제 대기(`pending`) 주문이 생기고, 테스트 결제창에서 승인하면 결제 키(`fake-<주문 번호>`)와 결제 금액으로 `confirmOrderPayment`를 불러 결제 완료(`paid`)가 됩니다. 결제를 마치면 백엔드가 주문한 장바구니를 지우고, 앱은 브라우저에 둔 장바구니 id와 입력하던 주문서를 지웁니다. 실제 PG를 연동하려면 `src/features/shop-checkout/fake-payment.tsx`의 "결제 승인" 대신 PG의 결제창(SDK)을 열고, PG가 돌려준 paymentKey로 같은 뮤테이션을 부릅니다. 비밀 키가 필요한 승인 요청과 금액 확인은 백엔드가 합니다.
- 가격은 `src/shared/shop/price.ts`의 `formatPrice`가 원화(`Intl.NumberFormat('ko-KR', { style: 'currency', currency: 'KRW' })`, 예: ₩19,000)로 적습니다.
- 명세: `openapi.yaml`의 `catalog` tag에 `listCatalogProducts`, `getCatalogProduct`, `cart` tag에 `createCart`, `getCart`, `addCartItem`, `updateCartItem`, `removeCartItem`, `orders` tag에 `placeOrder`, `getOrder`, `confirmOrderPayment`가 있습니다. Base의 상품 샘플(`products` tag의 `Product`)과 겹치지 않도록 카탈로그의 상품은 `CatalogProduct`입니다. 실패 이유는 `ShopError`(`message`)로 알립니다.
- Query Domain: `src/queries/catalog/`, `cart/`, `orders/`는 `npm run g -- query listCatalogProducts`, `query getCatalogProduct`, `query getCart`, `mutation createCart`, `mutation addCartItem --optimistic getCart`, `mutation updateCartItem --optimistic getCart`, `mutation removeCartItem --optimistic getCart`, `query getOrder`, `mutation placeOrder`, `mutation confirmOrderPayment`를 차례로 실행해 만든 코드에, 응답 전에 보일 장바구니를 만드는 `applyAddCartItem`, `applyUpdateCartItem`, `applyRemoveCartItem`만 채운 것입니다. 뮤테이션은 끝나면 자기 Query Domain 전체(`cartKeys.all`, `ordersKeys.all`)를 무효화합니다.
- Feature: 머리글 링크와 쇼핑몰 안 이동 `src/features/shop-nav/`, 상품 목록·상세 `src/features/shop-catalog/`(`npm run g -- page`가 만든 보기를 고친 것), 담는 폼과 장바구니 `src/features/shop-cart/`(`npm run g -- form addCartItem`이 만든 폼을 수량만 받게 고친 것), 주문서·결제창·주문 완료 `src/features/shop-checkout/`(multi-step-form Recipe의 `useFormSteps`·`StepForm`과 Base의 `useSchemaForm`으로 만든 단계, `checkout-steps.tsx`에 단계마다 제목·스키마·입력 요소·확인 단계의 값).
- 목 백엔드: `src/shared/mocks/shop.ts`가 명세의 example 상품으로 시작해 장바구니와 주문을 서버 프로세스의 메모리에 기억하고 재고를 확인합니다. 장바구니를 바꾸는 요청에는 1초 뒤에 답하고, 재고가 2개인 한정판 머그(6번)를 세 개째 담으면 늘 409로 거절합니다. 그래서 개발 서버에서도 응답 전에 바뀌는 모습과 되돌리기를 볼 수 있고, E2E가 테스트만을 위한 코드 없이 실패를 재현합니다. 주문해도 재고는 줄이지 않습니다. 확장 지점 `mockHandlers`로 생성된 핸들러보다 앞에 두고, 목 백엔드 주소(`MOCK_API_BASE_URL`)로 가는 요청만 받습니다. 서버를 다시 띄우면 처음 상태로 돌아갑니다. 실제 백엔드로 바꾸면 이 파일과 그 테스트(`shop.test.ts`), `src/shared/mocks/handlers.ts`의 `shopHandlers`를 지웁니다.
- 검색 노출: 장바구니, 주문서, 주문 화면은 `noindex`이고, sitemap을 만드는 Recipe(seo)와 함께 넣으면 sitemap에서도 빠집니다(`src/shared/shop/shop-routes.ts`의 `shopSitemapRules`). 상품 상세(동적 세그먼트)는 sitemap에 저절로 들어가지 않으므로, 필요하면 seo의 `src/app/sitemap.ts`에 상품 목록을 가져와 더합니다.
- 테스트: `src/shared/mocks/shop.test.ts`(장바구니와 합계, 재고 부족 409, 주문과 결제, 결제 금액 확인), `src/shared/shop/cart-id.test.ts`, `src/features/shop-catalog/catalog-product-list.test.tsx`, `src/features/shop-nav/shop-nav.test.tsx`, `src/features/shop-cart/add-to-cart-form.test.tsx`·`cart-view.test.tsx`(응답 전에 바뀌는 장바구니, 거절되면 다시 가져오기 전에 되돌리고 알림, 없는 장바구니, hydration 전에는 꺼진 담는 폼), `src/features/shop-checkout/checkout-form.test.tsx`(단계마다의 검증, 이전·수정, 장바구니 id와 함께 주문, 거절), `fake-payment.test.tsx`(결제 확인, 장바구니 id와 주문서 지우기, 주문 완료), `checkout-form.test.tsx`의 axe 검사(처음 화면, 검증 오류, 주문 확인), `e2e/commerce.spec.ts`(ISR로 미리 렌더링한 목록·상세, 상품 탐색 → 장바구니 → 주문서 → 가짜 결제 → 주문 완료, 재고 부족으로 거절된 담기·수량 변경의 되돌리기, 접근성).
- 쇼핑몰을 지우려면 `src/app/shop/`, `src/features/shop-nav/`, `shop-catalog/`, `shop-cart/`, `shop-checkout/`, `src/queries/catalog/`, `cart/`, `orders/`, `src/shared/shop/`, `src/shared/mocks/shop.ts`와 `shop.test.ts`(와 `handlers.ts`의 `shopHandlers`), `e2e/commerce.spec.ts`를 지우고, `src/app/app-shell.tsx`의 `ShopLink`(sitemap이 있으면 `src/app/sitemap-rules.ts`의 `shopSitemapRules`), `openapi.yaml`의 `catalog`·`cart`·`orders` tag와 경로, 스키마, 파라미터를 뺀 뒤 `npm run api:gen`을 실행합니다.
